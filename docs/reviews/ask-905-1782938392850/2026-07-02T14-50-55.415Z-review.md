## Executive Summary

This branch improves provider timeout handling in Actuarius by propagating partial stdout/stderr into typed timeout errors, building richer timeout reports with staged/unstaged diff context and detached-worktree awareness, reordering error classification to prioritize timeout over auth-failure detection, and adding fence-aware Discord message splitting. All three reviewers independently confirmed a behavioral regression introduced by the error-handler reorder: buffer-overflow errors from spawnCollect (which produce {code: 'EMSGSIZE', killed: true, signal: 'SIGTERM'}) now match the reordered timeout predicate at runProviderRequest.ts:212-214 before reaching the EMSGSIZE branch at line 236, causing large-output provider failures to be silently misreported as provider timeouts instead of the correct 'output exceeded buffer limit' failure. This is the sole merge blocker; the remaining findings are diagnostic-accuracy and test-coverage issues that do not block the core feature.

## Blocking Issues

- EMSGSIZE buffer-overflow misclassified as TIMEOUT (src/utils/runProviderRequest.ts): spawnCollect.ts:543-546 rejects stdout-buffer overflow with {code: 'EMSGSIZE', killed: true, signal: 'SIGTERM'}. The EMSGSIZE branch is dead code for the common signal-death path. Fix: move the EMSGSIZE check above both the timeout predicate and the authFailurePattern branch (lines 223-234) so that an overflow whose stderr coincidentally matches auth patterns is also not misclassified.
